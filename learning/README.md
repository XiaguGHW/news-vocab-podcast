# 个人词汇学习记录

`vocabulary.json` 是复习任务的权威数据来源。它不参与播客媒体构建。

## 新词与更新

用户已授权助手维护记录：在此项目的词汇学习、加入复习或作答后，将可见事实同步到 main；出题前先读最新文件，不要求用户重复授权。新的聊天若没有项目上下文，需提供本仓库或本文件位置，不能承诺自动看到所有对话。

- 用户明确学过、问过词义或要求复习的词可加入。从二零二六年十一月二十二日起，用户还明确授权以后每期已发布播客的目标词表自动加入复习池；不需要再次询问。自动加入不代表已经收听、作答或掌握。
- `excluded_words` 保存用户要求排除的词；导入新词或播客候选词时跳过，只有用户明确要求恢复才重新加入。
- 优先复用已有 id，按原形合并；保留词形。不同义项在 notes 中区分，必要时使用独立 id。
- 每次实际作答追加 history；仅出题、未回复时不写答题结果，也不推进复习日期。提示、遗忘、拼写、词形、近义词混淆分别记录。不要用单一分数抹掉区别。
- 每个事件有稳定唯一 event_id。写入前读最新版本并按 id 合并，重试同一事件不重复计数；事件已经写入但后续核实有误时明确追加更正依据。
- 已有历史不得静默删除。校正错误解析可以修改具体事件，但须在 note 写明更正原因。
- `updated_on`、`added_on`、`last_practiced_on` 和 `next_review_on` 均按柏林日期；不编造缺失时间。
- 修改后校验 JSON、词条 id 唯一、event_id 唯一、日期、外键及结果枚举；确认推送成功再说已保存。只提交相关学习文件。冲突时读取最新内容并合并，不强推。
- 若 GitHub 暂时无法读写，说明未同步，保留本轮待保存的实际结果，恢复后再同步；不得声称已保存。

## 字段与状态

- `status`: `reviewing`（有练习记录），`introduced_unassessed`（已介绍或已发布，尚未测验）。不使用“一次正确即已掌握”的标签。
- `priority`: `high` 或 `normal`，根据遗忘、提示、错误及用户自述调整；始终保留旧证据。同一天纠错答对不立即降优先级。
- `result`: `independent_correct`、`independent_correct_in_parts`、`hinted_correct`、`overcued_correct`、`not_recalled`、`spelling_error`、`form_error`、`word_confusion`；后续需新增类别时同时补充此说明。
- `hint_requests` 是明确要求提示的次数，不是总帮助量；助手主动提示或过强提示须写进 note。
- `next_review_on` 是下一次建议练习日期，不是已执行的预约或学习事实。

## 选题与复习间隔

先选到期的高优先级词；每轮通常三个薄弱词、一个近期新词、一个较早学词，名单不足时轮换，不把讲解过当作答对。

初始记录统一安排次日再练。以后可用简单启发式：遗忘、错误或有提示答对，次日再练；跨日首次无提示正确，约三日后再练；跨日再次正确，约七日后再练。不是科学上唯一最优间隔，用户反馈优先。同轮重测不能当成跨日成功。只在实际作答后调整日期；无人作答不推进。

每轮15题，一次一题并即时反馈；整轮进行中在当前对话暂存答题与提示情况，不更新仓库。完成15题或用户明确提前结束时，读取最新记录并一次性同步本轮实际作答，之后总结。若用户中途离开而未结束，本轮尚未同步，跨对话可能无法恢复。未来新增的词与作答按同一规则持续积累。

## 播客发布后自动同步

`sync_podcast_vocabulary.py` 只读取本次实际部署的音频源中各期的明确 `words`，包括批准发布的 `stories/`，不从故事正文任意提取词。
发布前先校验导入计划；部署成功后从 main 最新学习记录合并并提交。遇到并发答题更新时重新读取合并，非快进推送会重试，不强推、不覆盖学习历史。
重复词按已有原形或已登记词形合并，只补来源；需要导入新词形时提供 `lemma` 或 `forms`，不猜词形。排除词不重新导入。
新条目默认普通优先级、未测验、无答题历史，建议次日复习。现有条目的练习日、复习日、薄弱证据及历史保持不变。
`podcast_sync.json` 记录已处理期数的词表指纹，避免反复导入。启用时对已经发布的旧期建立基线，不批量回填旧新闻词；后续新发布或修改词表的期数自动同步。当前完整生词数量仍以 `vocabulary.json` 为准。
检查命令：`python sync_podcast_vocabulary.py --feed docs/feed.xml --check`。不完整时检查失败，不能声称同步完成。

## 位置与可见性

这是 GitHub 仓库文件，具有仓库相同的可见性，并非私有聊天存储；只记词汇、答题文本和必要教学备注，不添加个人身份信息或无关对话。
